# Music Transformer, reproduced and running in the browser

Before this project extends anything, the model it builds on had to exist here, trained from scratch and checked. Music Transformer (Huang et al., ICLR 2019) is the relative-attention Transformer for piano performances; the configuration Magenta released for it was re-implemented in PyTorch, trained for one million steps on the official MAESTRO v1 split, compared numerically with the original Tensor2Tensor code, and exported so that it runs inside a web page.

## Find the work

- [Music Transformer, reproduced](../../artifacts/music-transformer-reproduction.html): the numbers, learning curves, the parity check against the original code, the comparison with the paper, and continuations to hear.
- [Music Transformer, live](../../artifacts/music-transformer-live.html): the trained model running in the browser on any of twenty held-out openings or from silence, and a blind test: pianist or model?

## The numbers

The released configuration: 6 layers, width 512, 8 heads, 1,024-wide feed-forward, relative attention over 1,024 positions, 2,048-event context, 310-event vocabulary, 16.1 million parameters. One process on one GPU, batch one 2,048-event crop per step, 32 ms per step, 9.1 GPU-hours in all.

| Quantity | This reproduction | Paper, relative attention |
|---|---|---|
| Validation NLL, 128 fixed windows (the model-selection metric), best checkpoint at step 984,000 | 1.835 | 1.835 |
| Validation NLL, every validation event (2.20M) | 1.827 | — |
| Test NLL, every test event (2.29M), reported once | 1.801 | — |
| Final checkpoint (step 1,000,000), every validation event | 1.836 | — |

NLL is negative log-likelihood in nats per event, lower is better. The paper's figure is on the authors' own partition of the same Piano-e-Competition recordings with a 2,048-wide feed-forward layer, so the match on the selection metric is agreement, not identity. The test figure was computed once, after training, and is not used for any decision.

## The checks

- **Same function as the original code.** With identical weights and inputs, the PyTorch port and Tensor2Tensor 1.15.7 agree on the logits to 2.5 × 10⁻⁵, the loss to 1 × 10⁻⁶, and the gradients to a cosine of 0.999999 (experiment 023). The model is a new implementation, not a converted checkpoint.
- **Same model in the browser.** The exported graph (16-bit weights, 32-bit arithmetic, one decoding step with a key-value cache) matches the PyTorch model over 301 positions of a held-out opening: largest logit difference 0.011, the same most-likely event at every position, mean NLL 2.53407 against 2.53411.
- **Same notes.** The page's event decoder reproduces note_seq's decoding note for note on a 363-note sample, and its sampler applies the pool's nucleus rule.
- **Speed.** In headless Chrome on a single WebAssembly thread: 18 ms per event while reading a 512-event opening, 29 ms per event while composing, about 25 s for a 512-event continuation after a 20-second opening.

## Listening

The listening pool is fixed before anyone listens: twenty openings of 512 events from twenty distinct validation performances (nine composers), four continuations of 1,024 events each at temperature 1 and nucleus 0.98, seed 20261020, plus eight sequences of 1,536 events from silence. Every clip is rendered by the same FluidR3 piano, peak-normalised, so differences are in the notes. The reproduction page shows the first two candidates of the first eight openings in seed order; nothing is chosen by ear.

The blind test pairs each opening's first candidate with the pianist's own next 1,024 events from the recording. Both clips share the opening; the listener picks the pianist. With twenty rounds, fifteen or more correct is better than guessing at the 5% level. Answers stay in the listener's browser.

## What this changes

The baseline that the field's later numbers are measured against (Perceiver AR reports 1.82 on this benchmark at 4,096 context) now exists locally with its full training record, a sampler, an evaluation harness, a renderer, and a browser build. Extensions can be measured against it on the same held-out events rather than against a figure in a paper.
