What exactly runs, and how it was checked
GraphOne decoding step: next event in, logits and the extended key-value cache out (6 layers, 8 heads, relative attention over a 1,024-position table, 2,048-event context). The relative term for one query is its dot product with every relative embedding, gathered by each key's distance.
WeightsStored as 16-bit floats and cast to 32-bit inside the graph (the runtime folds the casts at load), so arithmetic is 32-bit. File hash 9ebb82972f6b3d4a…, from checkpoint 0d6bd8eb0231d5fc….
Check against PyTorchOver 301 positions of the first frozen opening: largest logit difference 0.011, identical most-likely event at 100% of positions, mean NLL 2.53407 (graph) against 2.53411 (PyTorch).
SamplingReserved ids masked; temperature, then nucleus filtering with the same rule as the pool sampler; a seeded 32-bit generator, so a seed replays. The pool itself was sampled on the GPU with seed 20261020; browser samples will differ from it by construction (different generator).
SpeedMeasured in this browser once the model runs.
Runtimeonnxruntime-web 1.30.0, WebAssembly backend, single thread (this site does not set cross-origin isolation headers). Prompt set v1 hash 9d5e74824c41f470….

Pianist or model?

Each round takes one of the 20 openings. Both clips begin with the same opening, played by the pianist. After it, one clip continues with the pianist's own next 1,024 events from the MAESTRO recording; the other continues with the model's first sample for that opening (candidate 0 at seed 20261020, never chosen by ear). Both are rendered by the same piano. Pick the pianist.
