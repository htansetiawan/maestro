Music Transformer, reproduced

The released Music Transformer configuration retrained on MAESTRO v1 in PyTorch, matched numerically to the original Tensor2Tensor code, with learning curves, the paper's comparison, and continuations to hear.

Page built October 21, 2026 · Training complete · Run the model in your browser

Permalink

Music Transformer (Huang et al., ICLR 2019) showed that a Transformer with relative attention models long piano performances better than one without it. This page retrains the configuration Magenta released for that paper, in a new PyTorch implementation, on the official MAESTRO v1 split, and reports what comes out: the numbers, the checks that the implementation computes the same function as the original code, and the music.

The numbers are not directly comparable, and the gap has known causes. The released configuration trained here has a 1,024-wide feed-forward layer; the paper's relative-attention model used 2,048. The paper used its own partition of the Piano-e-Competition recordings; MAESTRO v1 is the same recordings under a different, composition-level split. The released code uses an 88-key vocabulary of 310 events; the paper describes 128 pitches. The ablation runs listed above hold everything fixed but the attention type and the paper's layer sizes, so the comparison the paper actually makes, relative attention against a vanilla Transformer, is reproduced on this data.

The implementation computes the same function as the original

A port can look right and still differ. To rule that out, the same randomly initialized weights were loaded into this implementation and into the original Tensor2Tensor code (version 1.15.7, the version the released configuration was written for), and both were given identical inputs with dropout off.

Parity at float32 precision at lengths 64, 1024, 1100 and 2048. Loss agrees to <=1.3e-6, argmax of every logit row agrees, gradient cosines >= 0.999998, and at every length the T2T float32 result is as close to a float64 port reference as the port's own float32 result is, so the residual disagreement is float32 rounding rather than a semantic difference.

Every one of the 82 TensorFlow variables maps onto the 70 PyTorch tensors with nothing unmapped or unused. Same random weights loaded into both frameworks, dropout off, identical inputs, CPU float32; the original ran under Python 3.7 with TensorFlow 1.15.5 and Tensor2Tensor 1.15.7.

The split is by composition: no work appears in two splits. Training uses the train split; checkpoints are chosen on validation; the test split has not been used.

Known differences from the original run

  • PyTorch replaces TensorFlow. The function is the same to float32 rounding (above); random number streams, operation order, and bf16 arithmetic are not.
  • Dense layers are initialized with a fan-in bound; Tensor2Tensor uses fan-average. This changes the initial feed-forward weights slightly, not the computation.
  • Training crops are sampled with replacement over pieces, tempo variants, and transpositions; the original shuffles epochs of stored augmented copies.
  • MIDI is parsed directly with the released note-seq classes; the original consumed pre-built TFRecords from the same encoding.
  • Validation during training uses 128 fixed windows; the end-of-run number uses the original rule, every validation performance in consecutive 2,048-event chunks.

Reproduce it

python3 experiments/020_music_transformer_reproduction/prepare.py     # verify the archive, encode MAESTRO
python3 experiments/020_music_transformer_reproduction/check.py --cuda # attention, tokenizer, optimization checks
python3 experiments/020_music_transformer_reproduction/launch.py --run baseline-stage1 --steps 1000000
python3 experiments/020_music_transformer_reproduction/evaluate.py --checkpoint runs/baseline-stage1/best.pt
python3 experiments/020_music_transformer_reproduction/sample.py --checkpoint runs/baseline-stage1/best.pt --prompts prompts/v1.json --candidates 4 --new-tokens 1024 --top-p 0.98 --midi --out pools/v1
python3 experiments/020_music_transformer_reproduction/render.py pools/v1/*.mid

Prompt set v1 is frozen with its hash before any listening (v1, SHA-256 9d5e74824c41f470…). Listening clips come from checkpoint step 984000, SHA-256 0d6bd8eb0231d5fc…. MAESTRO is released under CC BY-NC-SA 4.0 by Google Magenta; the prompt clips are short excerpts of its validation performances.
